A continuación se integra el despliegue de Model Serving en producción usando Docker dentro del panorama que venimos construyendo.Para llevar modelos de IA a entornos de misión crítica (millones de transacciones/mes), no basta con ejecutar un archivo de Python o lanzar un ejecutable local como Ollama en un equipo de desarrollo. Se requiere empaquetar el motor de inferencia en contenedores aislados, optimizados para aceleración de hardware (GPU/NPU) y diseñados para escalado horizontal.1. Mistral, Llama 3 o un clasificador de fraude personalizado) a escala dentro de un contenedor Docker, se siguen tres pilares fundamentales:A. Uso de Imagen Base con Aceleración CUDA / GPUEl contenedor requiere acceso directo a los drivers de la tarjeta gráfica del host mediante NVIDIA Container Toolkit.Dockerfile# Ejemplo conceptual: Servidor de inferencia vLLM sobre CUDA
FROM vllm/vllm-openai:latest

# Pasar variables de entorno para optimización
ENV MODEL_NAME="mistralai/Mistral-7B-Instruct-v0.2"
ENV MAX_MODEL_LEN="8192"
ENV TENSOR_PARALLEL_SIZE="1"

# Exponer el puerto para la API REST/OpenAI compatible
EXPOSE 8000

CMD ["python3", "-m", "vllm.entrypoints.openai.api_server", \
     "--model", "mistralai/Mistral-7B-Instruct-v0.2", \
     "--port", "8000"]
B. Ejecución del Contenedor montando los GPUs del HostA diferencia de un microservicio Python tradicional, el contenedor de inferencia se lanza permitiendo el acceso explícito a la GPU:Bashdocker run --gpus all \
  -e HUGGING_FACE_HUB_TOKEN=$HF_TOKEN \
  -p 8000:8000 \
  --ipc=host \
  vllm/vllm-openai:latest \
  --model mistralai/Mistral-7B-Instruct-v0.2
Nota: --ipc=host es indispensable para permitir la memoria compartida entre procesos cuando se realiza paralelismo de tensores entre múltiples GPUs.4. Inferencia Asíncrona: El backend (FastAPI) recibe las transacciones, las coloca en una cola de mensajes (Kafka/RabbitMQ) y los contenedores de Model Serving en Docker consumen y procesan las ráfagas.Escalado Horizontal (K8s / HPA): Se configuran métricas customizadas en Kubernetes (ej. uso de memoria GPU o tamaño de la cola de inferencia) para levantar más réplicas en contenedores Docker cuando el tráfico de fraude/spam sube.Carga Eficiente de Pesos: Los pesos pesados del modelo no se empaquetan dentro de la imagen de Docker (para evitar imágenes de 30GB+), sino que se montan como volúmenes compartidos (volumes: - /models:/root/.cache) o se descargan al iniciar el contenedor desde una red privada (S3/MinIO).5. Resumen Consolidado para la EntrevistaOllama: "Es la herramienta ideal para prototipar rápidamente en local o integrar en flujos de desarrollo."Docker MCP Toolkit: "Es la infraestructura para empaquetar, aislar y dar acceso seguro a herramientas (bases de datos, APIs) a los modelos sin riesgos de ejecución arbitraria en el host."Model Serving en Docker (vLLM / TGI / Triton): "Es la estrategia estándar de producción para containerizar el motor de inferencia, montar acceso directo a GPUs, habilitar la gestión avanzada de memoria (PagedAttention) y escalar horizontalmente el procesamiento en plataformas de misión crítica."
